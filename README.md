# 风机故障诊断（第 1 轮框架）

给风电现场工程师用的网页工具：用口语或故障码查询，返回可能故障、原因、排查步骤，并留下手册 / Solution Center 引用位。

第 1 轮只搭骨架和每个部件 1 条示范案例，**不接大模型 API**，不导入真实手册。

## 怎么运行

需要本机有 Python 3（用静态文件服务，避免浏览器直接打开 `index.html` 时无法加载 JSON）。

```bash
cd firstRepository
python3 -m http.server 8080
```

浏览器打开：http://localhost:8080

可选：跑一遍匹配自检（需要 Node.js 18+）：

```bash
node engine/match.test.mjs
```

## 三块界面

1. **搜索**：顶部大输入框，口语 / 故障码均可；可点部件芯片。
2. **按部件浏览**：左侧部件目录，进入该部件下的故障模式（目录式）。
3. **案例详情**：故障名、原因、步骤、文档占位、相关度说明；「有用 / 不准」按钮仅前端占位。

## 知识长什么样

- `data/components.json`：部件主分类（14 个）
- `data/cases.json`：案例库。一条案例 = 一个故障模式，挂现象/同义词/故障码、原因、步骤、文档 id
- `data/documents.json`：文档库占位（标题、章节、出处），正文待后续导入

结构是：部件 → 故障模式 → 原因/步骤 → 文档引用。后面加案例不必改界面。

## 匹配怎么做（`engine/match.js`）

同一套 JSON，第 1 轮规则：

- **故障码**：查询里的 `F2101` 这类码与案例码精确命中（权重最高）
- **关键词**：故障名、同义词、现象、排查描述的子串命中
- **部件加权**：查询或芯片点到某部件时，该主部件案例加分，相关部件较小加分
- 按分数排序，最多返回 **2～3** 条，每条带「为什么命中」和文档引用槽
- 低于阈值：**库里没有匹配的案例**，并建议按部件浏览。不编唯一答案

第 5 轮若换 AI，只替换匹配模块，知识文件保持这个结构。

## 示范怎么试

| 输入 | 预期 |
| --- | --- |
| `偏航异响，报过偏航过载` | 偏航案例靠前，并可能带出刹车/液压等相关 2～3 条 |
| `变桨 1 轴跟不上` | 变桨不同步 |
| `F2101` | 变桨案例（精确故障码） |
| `F1234` 或无意义文本 | 空结果，提示浏览部件 |
